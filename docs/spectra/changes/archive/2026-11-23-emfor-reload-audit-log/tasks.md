## 1. 設定檔雜湊

- [x] 1.1 實作 requirement「Listing the files read」的 daemon 部分（design：「設定檔雜湊用原始位元組的 SHA-256」）。`crates/emfor-daemon/src/config.rs` 的 `Layers` 新增與 `files` 平行的 SHA-256 小寫 hex（`read_layers_with` 對每個成功讀到的檔案以 `sha256(text.as_bytes())` 算）；`crates/emfor-daemon/src/cli.rs` 的 `ReadFiles` 帶著雜湊（不論有沒有 `include_dir`），`log_files_read` 每個檔案記一行 info `config file read`，帶 `file`、`sha256` 欄位；啟動成功、reload 成功與被驗證拒絕的 reload 都記；讀不到檔案時不記雜湊。驗證：`config.rs` 單元測試——主檔無 `include_dir`、含兩個片段，雜湊等於測試內獨立算出的 SHA-256；`crates/emfor-daemon/tests/` 整合測試——daemon 啟動後 log 有 `config file read` 與 `sha256sum` 相同的值（沒設 `include_dir`），改檔 SIGHUP 後值改變，驗證失敗的 reload 仍記新雜湊且有 `reload rejected`；測試帶 `// spectra-scenario: service-config / Daemon logs the hash of every file read` 與 `... / Rejected reload still logs the hashes` 註解；`tools/docker-test.sh` 內通過。

## 2. 差異稽核

- [x] 2.1 實作 requirement「Configuration audit log」的差異計算（design：「差異在 cli.rs 以純函式算，不碰 Supervisor::sync」、「事件與固定欄位」、「絕不記 check_options 的值」）。新模組 `crates/emfor-daemon/src/audit.rs`（在 `lib.rs` 或 `main.rs` 註冊）：`Change` enum 與 `changes(old: &Config, new: &Config) -> Vec<Change>`，涵蓋 service 增減、backend 增減與 `weight`／`site`／`backup`／`drain` 變更、service 的 `check`／`interval`／`timeout`／`rise`／`fall`／`jitter`／`on_all_down`／`balance`／`peers`／`slow_start`／`dns_ttl` 變更、檢查定義變更（`digest` 舊新與 `resets_state` 取自 `check_changed`）、聯防 members 增減與 `encrypt`／`accept_plaintext`／`secret_file`／`previous_secret_file` 變更（`applies`），順序依設計（service 名稱字母序、service 層先於 backend 層、backend 依 id、最後聯防）。驗證：`audit.rs` 單元測試涵蓋 spec 範例表「change values」的每一列與五個情境的差異部分（含 `timeout` 單獨變更 `resets_state=false`、選項或檢查名變更 `resets_state=true`、無差異回空、`site` 未設寫 `-`），帶 `// spectra-scenario: service-config / Configuration audit log` 與 `... / Configuration audit log / change values` 等註解；`tools/docker-test.sh 'cargo test -p emfor-daemon --lib audit::'` 通過。
- [x] 2.2 [after: 2.1] 實作記錄與接線（design：「每次 reload 最多 50 行差異」、「不記的東西與誰改的」）。`audit::log_changes` 以 tracing info 與固定欄位名記每個事件，最多 `MAX_AUDIT_LINES = 50` 行，其餘一行 `change=more`、`omitted=N`；`cli.rs` 的 SIGHUP 成功分支在 `supervisor.reload(&new)` 之後、`config reloaded` 之前呼叫（舊設定為 `current`）。驗證：單元測試——80 個 service 新增得 50 行加一行 `omitted=30`；輸出文字不含 `check_options` 的值，也不含密鑰內容（以測試用的獨特字串斷言）；`crates/emfor-daemon/tests/` 整合測試——加一個 backend 並 drain 另一個後 SIGHUP，log 有 `change=backend_added` 與 `change=backend_changed` `field=drain`，都在 `config reloaded` 之前，沒有差異的 reload 沒有 `change=` 行；帶 `// spectra-scenario: service-config / Backend added and another drained`、`... / Check options changed without exposing them`、`... / More than fifty differences`、`... / No difference`、`... / Peer group changes` 註解；`tools/docker-test.sh` 內通過。
