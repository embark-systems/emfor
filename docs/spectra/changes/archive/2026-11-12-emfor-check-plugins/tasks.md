## Change notes

- 驗證方式調整（2.2、4.2）：「`--check-config` 拒絕未知的外掛參數」原列在 2.2，因 `emfor-check` 的測試拿不到 `emfor` 執行檔（Cargo 只提供同一個 crate 的執行檔路徑），改在 4.2 的容器中以真實 daemon 驗證。「failover 選到主庫」以 DNS SRV 驗證：daemon 沒有查詢指令，兩台後端都在 127.0.0.1，只有 SRV 帶埠號。
- design 更正（1.1）：daemon 沒有使用 rustls-native-certs（reqwest 走 rustls-platform-verifier），由 emfor-check 自行加入；PEM 解析用 rustls-pki-types，不加 rustls-pemfile。mysql_async 不接受自訂 ClientConfig，以 SslOpts 組出相同語意。
- 實作補充（2.3）：`server_name` 另須是合法的主機名或 IP（`not a valid host name or IP address`），否則 TLS 名稱無法建立。
- 實機測試後修正（4.1）：TLS 握手最多用剩餘檢查時間的 90%，逾時回 `tls: no answer to the TLS handshake (does the port speak TLS?)`，讓 "Server without TLS" 情境在 redis 這類收到握手後不回應的明文伺服器上也是 `tls: `；被驅動包在 I/O 錯誤裡的 rustls 錯誤一律回 `tls: `。
- 量測：自寫的 RESP 編解碼 `crates/emfor-check/src/resp.rs` 測試以外 156 行（含註解），符合 design 約 150 行的估計。`emfor-plugins-test` 映像 997 MB。

- 另行處理（2026-11-12）：5.2 提到的 `crash_and_recovery` 偶發失敗已在同一個 session 修正（不屬於這個 change 的規格範圍）。測試用外掛新增 `EMFOR_TEST_PLUGIN_BLOCK_FILE`：檔案存在時啟動即結束；測試在殺掉外掛前建立該檔案，等 store 出現 `plugin` 開頭的 error 原因後才刪除，讓中斷期間必定跨過 store 每秒一次的寫入，`fall` 由 15 改為 40 使 8 秒大於最長約 3 秒的中斷。驗證：macOS 該測試連跑 3 次、`tests/plugins.rs` 13 個測試通過；Debian 映像 clippy 通過，`cargo test --workspace --all-features` 連跑 5 次全部通過（37 個測試套件）。
- verify 與 review 後修正（2026-11-12）：(1) 檢查時 `password_file` 讀不到原本回 `check_options: password_file: ...`，現在 `options::parse`（validate 用，會讀檔）與 `options::settings`（check 用，不讀檔）分開，檢查時讀檔失敗回 error `password_file: ...`（新增 `tests/cli.rs` 的 `password_file_removed_after_validation_is_error`）；(2) 密碼檔不是 UTF-8 時在 validate 就報錯；(3) 剩餘時間不足 100 ms 時不再把逾時算成 `tls: `，改用檢查本身的 timeout（新增 `little_time_left_is_not_blamed_on_tls`）；(4) `tests/plugins/inside.sh` 新增 `--check-config` 顯示 mysql 缺 `user` 的錯誤；(5) pgsql 在回答前等連線關閉，最多 100 ms。驗證：macOS fmt、clippy、test 通過；`tests/plugins/run.sh` 通過；Debian 映像 clippy 通過，`cargo test --workspace --all-features` 連跑 2 次全部通過（37 個測試套件）。
