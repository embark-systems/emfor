  - 完成紀錄（2026-11-13）：`radius::parse` 的單元測試涵蓋範例表十列、"Status-Server with a secret" 的預設值、其他型別與檔案錯誤（`password` 為 unknown key、檔案不存在、`application`、布林、`nas_identifier` 254 位元組、`request` 非字串），以及 check 時不讀檔；`tests/cli.rs` 的 `radius` 握手通過。`lib.rs` 的資料庫分支抽成 `check_database`，dns 與 radius 誤入時回 `internal: ` error。`request` 無效時略過依 `request` 而定的規則，避免連帶錯誤。
- [x] 1.2 依「MD5 and HMAC from crates already in Cargo.lock」與「Message-Authenticator first in every request」實作 RADIUS 封包編碼：Status-Server 與 Access-Request（依「Access-Request with PAP for end-to-end checks」以 RFC 2865 5.2 隱藏 User-Password）、Message-Authenticator 為第一個屬性、NAS-Identifier；以及回應的解析與驗證（長度、Response Authenticator、Message-Authenticator，依「Always verify the response authenticator」）。驗證：單元測試以 RFC 2865 第 7.1 節的範例封包確認 User-Password 與 Response Authenticator 的計算（spec "Password hidden as in RFC 2865"）、以 RFC 3579 的計算方式確認 Message-Authenticator，並通過；`cargo tree -p emfor-check -e normal` 確認 `Cargo.lock` 沒有新增套件，結果寫進完成紀錄。
  - 完成紀錄（2026-11-13）：RFC 2865 7.1 範例（密鑰 `xyzzy5461`、`arctangent`）的 User-Password 與 Response Authenticator 計算一致；HMAC-MD5 以 RFC 2104 測試向量 1 確認；請求的 Message-Authenticator 以 RFC 3579 的方式（值歸零後 HMAC）驗證並確認為第一個屬性。`Cargo.lock` 唯一變動是 emfor-check 的相依列多了 `hmac`、`md-5`、`rand 0.10.3`，沒有新增套件（三者原本就在，md-5 與 hmac 同用 digest 0.11）。spec 沒規定的邊界：user 超過 253 位元組或密碼超過 128 位元組（RFC 2865 上限）時檢查為 error 且不送出請求（`too_long_logins_are_errors`）。verify / review 後改為在驗證設定時就拒絕：`user` 須為 1–253 位元組（`must be 1 to 253 bytes`）、radius 的 `password_file` 密碼最多 128 位元組（`password longer than 128 bytes`），spec 與 design 一併更新；check 時的檢查保留，密碼檔事後被改長仍為 error（`login_lengths_are_checked_when_validating`，拿掉長度檢查時失敗）。同時修正 `emfor-check` 的 usage 行漏列 radius、`options.rs` 的過時註解、design 中 `status_server` 的位置（`radiusd.conf` 的 `security` 區段）。反向檢查：拿掉密碼區塊串接時 `long_passwords_chain_the_blocks` 失敗。
- [x] 1.3 依「Status-Server as the default request」實作 "RADIUS check" [after: 1.1, 1.2]：每次檢查重讀密鑰與密碼（讀不到為 error 且不送出請求），經 `net.rs` 的 UDP 收發送出，依 spec 四步判斷與 Reply-Message 規則產生結果。驗證：單元測試以本機假 RADIUS 伺服器涵蓋 spec "RADIUS outcomes" 範例表十一列、"Server answers Status-Server"、"Wrong shared secret"、"Secret file removed"、"Server without Status-Server support" 並通過；另以測試確認所有原因與 stderr 都不含密鑰與密碼。
  - 完成紀錄（2026-11-13）：radius 單元測試共 19 個通過，含結果表十一列（每列也確認原因不含密鑰與密碼）、Status-Server、密鑰錯誤、密鑰檔與密碼檔被刪（error 且假伺服器收到 0 個請求）、不支援 Status-Server（timeout，送出兩次）、20 位元組資料報的 Length 40、Reply-Message 串接與非 UTF-8 取代、其他 Identifier 的回應被忽略。假伺服器同時驗證每個請求的 Message-Authenticator 與隱藏後的密碼。反向檢查：拿掉 Response Authenticator 驗證時 `response_authenticator_as_in_rfc_2865` 與 `wrong_shared_secret` 失敗。plugin 不寫 stderr，原因只來自程式內的固定字串與 Reply-Message。
