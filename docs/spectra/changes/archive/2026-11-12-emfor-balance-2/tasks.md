## 1. Store format

- [x] 1.1 In `emfor-format`, `Balance` gains `Weighted` (`"weighted"`), `Locality` (`"locality"`) and a catch-all `Unknown` variant (`#[serde(other)]`) so that "Unknown balance falls back to round-robin" can parse any value; `BackendRecord` gains `weight: u32` (serde default 1) and `site: Option<String>` (serde default `None`); a constant `KEY_SITE = "meta/site"` is added. Verified by new unit tests in crates/emfor-format/src/lib.rs: `"some-future-method"` parses to `Unknown`, a backend object without `weight`/`site` parses with weight 1 and no site, and the "Store record format version 1" record-shape example serializes byte-for-byte with `"weight":1,"site":null`.

## 2. Daemon

- [x] 2.1 [after: 1.1] Config: "Backend table entries carry weight and site" — `backends` accepts strings and `{ addr, weight, site }` tables, the top-level `site` is read and lowercased, `balance` accepts `weighted` and `locality`, and every rule of "Config validation rules" and "Host site and backend weight and site" is enforced with its TOML path. Verified by unit tests in crates/emfor-daemon/src/config.rs covering every row of the validation-outcomes example table and the mixed-backend-forms scenario, plus `emfor --check-config` on examples/emfor.toml exiting 0.
- [x] 2.2 [after: 2.1] Writer: "Store records carry weight and site, and meta/site holds the host's site" — every backend record is written with `weight` and `site`, `meta/site` is written on start when `site` is set, and a reload that sets, changes or removes `site` writes or deletes `meta/site`; a reload that changes a weight rewrites the record. Verified by writer unit tests for the "Host site written and removed" and "Weight change applies on reload" scenarios and the "weight and site written" example.
- [x] 2.3 [after: 2.1] DNS selection: "Balance methods" covers five values; "Weighted choice in the daemon" uses smooth weighted round-robin per service and family with the state reset when the candidate list changes; "Locality choice in the daemon" narrows to the host site's candidates, then round-robin with the per-family counter. This implements the DNS half of "Weighted choice by cumulative ranges in clients and smooth weighted round-robin in DNS" and "Locality narrows the candidates, then round-robin". Verified by unit tests in crates/emfor-daemon/src/select.rs and crates/emfor-daemon/src/dns.rs reproducing every row of the answer-order and locality-outcomes examples, the unhealthy-heavy-backend scenario, and a state reset after a health change.
