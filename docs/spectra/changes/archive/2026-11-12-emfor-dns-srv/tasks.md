## 2. DNS answers

- [x] 2.1 "SRV target names" per "Target names are derived from the backend IP": a helper in crates/emfor-daemon/src/dns.rs computes the IP label (IPv4 dotted with `-`, IPv6 as eight 4-digit lowercase groups joined by `-`), and `answer` returns A or AAAA for a target name with the backend's address regardless of health and with the service TTL, NODATA with SOA for other types on it, and leaves non-matching labels to the existing classification. Verified by unit tests in dns.rs reproducing every row of the target-labels example and the "Target of a down backend" scenario.
- [x] 2.2 [after: 1.1, 2.1] SRV answers on service names and SRV owner names, per "SRV owner names: the service name and `_<label>._tcp.<service>`": `answer` handles SRV on a service name ("Answers for service names") and on `_<label>._tcp.<service>`, treats `_tcp.<service>` and non-SRV types on owner names as NODATA ("Answers for names that are not services"), checks exact service names first, and fills the new `Reply.additionals` with one A/AAAA glue record per distinct target in answer order with the service TTL ("SRV answers"); the handler passes `additionals` to `MessageResponseBuilder::build`. Verified by unit tests in dns.rs reproducing the SRV row of the replies-by-case example, every row of the SRV-owner/empty-non-terminal/target example, and the Both families listed, Shared IP and SRV TTL scenarios; the existing dns.rs tests pass unchanged apart from setting `additionals`.
- [x] 2.3 [after: 2.2] Glue trimming and the UDP size limit, per "SRV responses fit the transport", "Glue records go in the additional section, all or none" and "UDP size limit follows the client's advertised size": the handler computes the limit from the transport and the request's EDNS size (clamped 512–1232, 512 without EDNS, 65535 over TCP), sets the response's EDNS size to that limit, and drops all glue when the encoded response with glue exceeds it, through a pure helper that encodes the response with hickory-server's own `MessageResponseBuilder` and encoder. Verified by unit tests for every row of the size-limit example, a reply whose glue is dropped with TC clear, and a reply whose SRV records alone exceed 512 bytes; the test also measures the backend counts at which glue and then SRV records stop fitting in 512 and 1232 bytes for IPv4 targets under `api.svc.emfor`, asserts them, and records the measured values in design.md "Sizes are measured by a test".
